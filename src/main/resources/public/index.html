Passkey-Demo

Platzhalterseite des Referenzservers – src/main/resources/public/index.html

Was eine Browser-Demo zeigen kann und was nicht Im Browser läuft eine echte WebAuthn-Zeremonie: Challenge, Nutzerverifikation, Signatur, Prüfung auf dem Server. Eine Attestierung zeigt sie nicht. Plattform-Passkeys (iCloud Keychain, Google Password Manager) liefern immer fmt=none. Nur eine native App liefert android-key bzw. packed plus Apple-App-Attest-Objekt. Alles, was hier registriert wird, trägt deshalb attested=false.

Diese Seite ersetzen

Der Server serviert /demo aus dem Verzeichnis staticDir (Standard: ./public neben application.properties). Existiert es, hat es Vorrang vor dieser eingebauten Seite. Beides nur bei attestationPolicy=demo.

Demo-API (nur bei attestationPolicy=demo, sonst 404)

  • GET /demo/api/status
  • POST /demo/api/register/options – {"username":"…"}
  • POST /demo/api/register/verify – {"ceremonyId":"…","credential":{…}}
  • POST /demo/api/login/options – {"username":"…"} (optional)
  • POST /demo/api/login/verify – {"ceremonyId":"…","credential":{…}}
  • GET /demo/api/list?username=…
  • POST /demo/api/reset – {"username":"…"}
lade /demo/api/status …
Die Compliance-Endpunkte der App liegen unverändert unter <basePath>/rest/authentication/passkey/… (basePath, Standard /api) und verlangen Bearer-Token, Passwort und – je nach Plattform – App-Attest.
